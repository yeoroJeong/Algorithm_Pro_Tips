B형(Pro) C++ 풀이 팁 C++

문제 설명의 그림·조건·API 호출 구조를 보고 어떤 알고리즘과 자료구조를 먼저 떠올려야 하는지 시각적으로 정리한 실전용 가이드입니다.

업데이트: 이제 각 카드의 이미지를 클릭하면 해당 유형에 맞는 B형 스타일 실제 코드 예시 + 추가 해설을 모달로 볼 수 있습니다.
🧠 그림 → 알고리즘격자, 가중 그래프, 트리, 집합 그림을 보고 후보 알고리즘을 빠르게 좁힙니다.
⚙️ API → 자료구조add/remove/query 반복 구조면 원본 저장소 + 보조 인덱스를 먼저 떠올립니다.
⏱️ 호출 횟수 → 복잡도query가 10,000번이면 전체 순회 O(N)을 그대로 넣어도 되는지 먼저 계산합니다.
📚 STL → 적절한 인덱스unordered_map, set, PQ, vector 등 각 STL의 템플릿 인자와 시간복잡도까지 바로 확인합니다.

빠른 의사결정 트리

시험장에서 먼저 스스로 물어볼 질문들

격자 / 그래프에서 최단거리?

  1. 이동 비용이 전부 같은가? → 같으면 BFS
  2. 가중치가 0 또는 1뿐인가? → 0-1 BFS
  3. 가중치가 모두 0 이상인가? → 다익스트라
  4. 가중치 대신 단순 연결 그룹인가? → DFS/BFS로 연결 요소

API형 문제인가?

  1. ID로 바로 찾아야 하나? → 배열 / unordered_map
  2. 정렬 순서 조회가 필요한가? → set / map / priority_queue
  3. 중간 삭제가 있는가? → set 또는 PQ + lazy deletion
  4. 구간 질의가 반복되는가? → Fenwick / Segment Tree

이런 그림/조건이면 무엇을 떠올릴까?

카드 이미지를 클릭하면 코드 예시와 추가 해설을 확인할 수 있습니다.

격자 + 상하좌우 이동 + 도착점

이 그림이면 먼저 거리의 정의부터 확인

→ BFS / 다익스트라 후보
모든 이동 비용이 1이면 BFS. 칸마다 비용이 다르거나 이동 비용이 가중치면 다익스트라.
가중치가 있는 그래프 + 모든 간선 비용 ≥ 0

정점별 최단거리를 저장

→ 다익스트라
dist[node]를 두고, PQ에서 꺼낸 값이 최신 거리인지 확인합니다.
간선 비용이 0 또는 1뿐

PQ보다 deque가 더 간단

→ 0-1 BFS
비용 0이면 push_front, 비용 1이면 push_back.
여러 덩어리 / 섬 / 연결 요소

“몇 개의 그룹인가?”

→ DFS / BFS
방문하지 않은 정점에서 탐색을 새로 시작할 때마다 연결 요소 개수가 1 증가합니다.
집합 합치기 + 같은 그룹인지 반복 확인

간선 전체를 매번 탐색하지 말기

→ Union-Find
find()로 대표자를 찾고 union()으로 합칩니다.
현재 최댓값/최솟값 또는 Top-K를 반복 추출

정렬 전체를 매번 하지 말기

→ priority_queue
중간 삭제가 필요하면 lazy deletion + version을 먼저 검토.
값 변경 + 구간 합/최소/최대 질의가 반복

배열 전체를 매번 순회하지 않기

→ Segment Tree / Fenwick
합만 필요하면 Fenwick이 단순. 복합 정보면 Segment Tree.
접두사 기준 검색 / 자동완성 / prefix 집계

문자열 전체 비교를 반복하지 않기

→ Trie
노드에 cnt, bestId 같은 집계값을 함께 저장.

유형별 C++ 실전 팁

검색과 좌측 메뉴로 필요한 유형만 골라 볼 수 있습니다.

원본 저장소 + 보조 인덱스

한 객체를 ID로 찾기도 하고, 점수/시간/우선순위 순으로도 찾아야 한다면 저장소를 하나만 두지 않습니다.

unordered_map<int, Data> byId; set<tuple<int,int,int>> byPriority;
실전 포인트: 값이 바뀔 때는 erase → 값 변경 → insert. 그리고 아래 의사 카드의 “원본 저장소 + 보조 인덱스” 케이스 이미지를 클릭하면 더 긴 예시 코드를 볼 수 있습니다.

Priority Queue + Lazy Deletion

PQ는 중간 삭제가 불편합니다. 오래된 노드를 남겨둔 뒤 top에서 걸러냅니다.

if (removed[id] || ver != version[id]) pop();
자주 나옴 값 변경 시 version 증가 후 새 노드를 push. “왜 삭제 안 하고 그냥 두지?”를 이해하는 것이 중요합니다.

BFS vs Dijkstra 구분

  • BFS: 모든 간선 비용 동일
  • Dijkstra: 비용이 서로 다르지만 음수는 없음
  • 0-1 BFS: 비용이 0 또는 1
격자 그림이 나왔다고 BFS 확정이 아닙니다. “높이 차이”, “스태미나”, “통행료” 문장을 찾으세요.

API 호출 횟수부터 역산

예: query 10,000번 × 데이터 100,000개 전체 순회 = 최대 10억 수준.

핵심 질문: query를 빠르게 만들기 위해 add/update 시점에 미리 인덱스를 유지할 수 있는가?

🔥 B형에서 바로 쓰는 STL 선택 가이드

비슷한 STL끼리 비교하고, 클릭하면 실제 API형 풀이 패턴까지 확인합니다.

문제 풀이 순서: 문제 문장 속 조회 기준을 찾고 → 그 기준마다 필요한 인덱스를 정하고 → add / remove / query 호출 횟수를 곱해 시간복잡도를 검증합니다. STL은 그 다음에 선택합니다.

🧺 unordered_set / set

존재 여부만 빠르게 볼 것인가, 정렬 순서까지 필요할 것인가?

“해당 ID가 현재 존재하는가?”“가장 작은/큰 값”, “정렬 순서”, “lower_bound”삭제/삽입이 계속 발생하면서 중복 없는 후보군을 관리

🗂️ unordered_map / map

ID → 객체를 O(1)에 찾을 것인가, Key 정렬까지 유지할 것인가?

mID, 주문번호, 객체 ID로 구조체를 바로 찾아야 함Key 순서대로 순회하거나 lower_bound가 필요B형 API에서 원본 저장소 역할로 가장 자주 쓰는 조합

📦 vector / deque / list

연속 순회, 양끝 처리, 중간 삭제 중 무엇이 핵심인가?

순회/인덱스 접근이 많음앞/뒤 삽입·삭제가 모두 많음특정 위치(iterator)를 이미 알고 있고 중간 삭제가 매우 잦음

🚦 queue / deque / priority_queue

들어온 순서인가, 0/1 비용인가, 우선순위인가?

모든 간선 비용 동일 + 최단거리가중치가 0/1가장 작은 비용/가장 높은 우선순위를 반복 추출

🧩 pair / tuple

문제의 우선순위 문장을 그대로 자료형으로 옮기기

좌표 {r,c}, 간선 {next,weight}, 다익스트라 {cost,node}우선순위 조건이 3개 이상set / priority_queue에서 custom comparator를 줄이고 싶음

🛠️ find / lower_bound / remove / sort

STL 알고리즘을 쓰기 전에 컨테이너와 호출 횟수를 같이 보기

한 번 정렬 후 여러 이분 탐색특정 값 전체 삭제단순 선형 탐색

📚 B형 C++ STL 치트시트

템플릿 인자 → 시간복잡도 → 언제 쓰는지 → 실전 함정까지. 카드를 클릭하면 상세 코드가 열립니다.

STL 선택 기준: 각 카드의 상세 창에는 주요 멤버 함수·알고리즘·시간복잡도·주의점을 표로 정리했습니다.

빠른 선택: ID로 즉시 찾기 → unordered_map · 정렬 유지 → set/map · 최상위 반복 추출 → priority_queue · BFS → queue · 0-1 BFS → deque. B형에서는 한 자료구조만 고집하기보다 원본 저장소 + 조회 기준별 보조 인덱스를 조합하는 경우가 많습니다.
